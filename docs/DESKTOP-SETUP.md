# Setting up FastSuite on the desktop (the benchmark machine)

The desktop (16 cores, 48 GB) is the only benchmark machine — Io is gone.
This file is the exact sequence: clone, install the pixi env, build, verify,
then the bench harnesses are ready. Everything here was verified on the
laptop first; the desktop follows the same steps.

## 1. Clone

```fish
# from wherever you keep your checkouts on the desktop
git clone git@github.com:RaphaelRibes/FastSuite.git
cd FastSuite
```

The repo is public; the SSH key needs its passphrase (1110), or clone over
HTTPS if that is easier:

```fish
git clone https://github.com/RaphaelRibes/FastSuite.git
```

## 2. Install the pixi env (once)

The root `pixi.toml` is the dev environment: rust `>=1.99,<2`, pkg-config,
cmake, a C compiler, zlib and zstd (flate2's zlib-ng builds from source).

```fish
pixi install
```

Takes a few minutes the first time (it builds the C deps). Each tool also
carries its own `pixi.toml` (fastcheck/dedup/prep/sim/maps/helper), but the
**root env is enough** — `pixi run` at the root builds and tests all six.

## 3. Build every tool

```fish
pixi run build
# or, if the pixi registry cache is already warm (the laptop's case):
pixi run build-offline
```

Six release binaries land in `tools/<tool>/target/release/`.

## 4. Verify (must be green before any bench)

```fish
pixi run test          # 852 tests, 0 failures (2026-10-23)
pixi run doctor        # all six tools found + versions
bash examples/demo.sh 20000
# the differential harness (fastcheck's correctness gate):
cd tools/fastcheck && python3 tests/differential.py ../../examples/runs/demo/sim_E/sim_R1.fastq.gz && cd ../..
```

`doctor` must list: fastcheck 0.1.0, fastdedup 1.3.0, fasthelper 0.1.0,
fastmaps 0.1.0, fastprep 0.5.0, fastsim 0.1.0.

## 5. The bench harnesses

The five bench repos live **on the laptop** in `~/work/<Tool>-Bench/` and are
**local-only (no remote — never pushed)**. To bench on the desktop:

```fish
# copy the bench repos over (they hold code + committed results.csv, never reads)
rsync -a laptop:work/FastCheck-Bench/ ~/work/FastCheck-Bench/
# …repeat for FastPrep-Bench, FastSim-Bench, FastMaps-Bench, FastHelper-Bench
```

Then, per bench (example — fastcheck):

```fish
cd ~/work/FastCheck-Bench
pixi run python scripts/run_bench.py \
  --fastcheck ~/FastSuite/tools/fastcheck/target/release/fastcheck \
  --fastsim  ~/FastSuite/tools/fastsim/target/release/fastsim \
  --fastqc   .pixi/envs/default/bin/fastqc \
  --falco    .pixi/envs/default/bin/falco
pixi run plot        # → results/*.svg
```

The comparators (fastqc, falco, fastp, cutadapt, multiqc) install per bench
repo — each bench's README lists its exact reproduce commands and its pixi
env. **The reads are regenerated by each bench's generator (seeded, never
committed) — nothing derived from real data ever lives in a repo (D-11).**

## 6. Running the campaign (PLAN-ML-LOCAL)

The queue-file coordination in `docs/PLAN-ML-LOCAL.md`: the laptop prepares
`campaign/queue/` (one cell file per dataset), the desktop consumes:

```fish
# on the desktop
rsync -a laptop:campaign/queue/ campaign/queue/
for cell in campaign/queue/*.cell
    if mkdir campaign/locks/(basename $cell).lock 2>/dev/null
        pixi run cell $cell
        rsync -a results/ laptop:campaign/done/
        rm campaign/queue/$cell campaign/locks/$cell.lock
    end
end
```

**The campaign has already run** — the fitter's short-insert defect was fixed in
the 2026-10-21 review round; see STATUS.md "Where the ML campaign stands".

## Notes

* **`pixi install` at the root is the only env you need.** The per-tool
  pixi.tomls exist for the future bioconda packaging (D-3), not for daily use.
* The build needs ~2 GB of disk per tool's `target/`; the benches need
  several GB more for generated reads (the 20M-pair fastcheck set is 1.9 GB
  per mate).
* If a bench script fails with "fastsim refuses to overwrite": pass
  `--force` — that refusal is fastsim's (correct, new) default; the scripts
  have been updated to pass it.
