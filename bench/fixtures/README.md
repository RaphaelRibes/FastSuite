# FastSuite pathology corpus

A committed set of adversarial test fixtures, each engineered to reproduce — as
a checkable input rather than a prose bug report — one of the **five defects the
Phase D campaign found only by measuring real sequencing data**.

## Why this exists

All five Phase D defects were found by **real-data measurement**. The 461-test
unit suite found **zero** of them. The suite tests the code *as written*; these
fixtures test the code against the *inputs that break it*. That is the gap this
corpus closes: a fixture that a defect fails on is the only kind of test that
catches that defect when it is reintroduced.

The five defects and the fixture that regresses each one:

| # | Defect | Fixture | Assertion that fails pre-fix |
|---|--------|---------|------------------------------|
| 1 | fastsim 3′ boundary rule: guard `t < read_len` fired at `t == 0`, forcing every read's **last base non-G** (sim 0.42% G vs real ~23.5%) | `notail_profile.json` | simulate from a no-tail, GC-rich profile → last-position G fraction drops to ~0 instead of staying ~0.25 |
| 2 | fastcheck profile `dup_rate` used `accs.first()` (R1 only) while the report uses the merged R1+R2 table | `paired_dup_R1/R2.fastq` | mates with different dup rates → profile `dup_rate` ≠ report `duplication_level` (profile reports the ~0 first-mate rate) |
| 3 | fastcheck k-mer counter ran an O(n) singleton eviction on **every** insert once past the 1M cap → 40 min CPU, frozen RSS on DRR509062 | `kmer_saturation.fastq` | **see caveat below — not reproducible as a fast fixture; guards the fix, does not repro the hang** |
| 4 | Phred+64 libraries decoded as Phred+33 → mean_q 62-68, physically impossible | `phred64.fastq` | quality bytes 66-105 decoded as +33 → mean Q ~52 instead of the plausible 20-40 band; and auto mode must *declare* the +33/+64 ambiguity, not silently guess |
| 5 | N-heavy padding dominated the duplicate count (NNNN… ×276 on one dataset) while the simulator emits zero Ns | `nruns.fastq` | repeated N-runs must be counted as duplicates: `duplication_level` reflects them and the top repeated sequence is the N-run |

All five fixes are present in the current source, so every fixture passes today.
Each is written to **fail loudly** if its defect is reintroduced.

## Fixtures

Generated by `make_fixtures.py` (committed, deterministic — fixed seeds), and the
generated bytes are committed to `bench/fixtures/` so the integration test does
not need Python to run. Regenerate with:

```
python3 bench/fixtures/make_fixtures.py
```

| File | Size | Reads | Role |
|------|------|-------|------|
| `notail_profile.json` | ~1.7 KB | — | fastsim profile, `tail = {0:100}` (no tail artefact), GC 0.70 — drives defect 1 |
| `paired_dup_R1.fastq` | ~100 KB | 600 | paired input, R1 diverse — drives defect 2 |
| `paired_dup_R2.fastq` | ~100 KB | 600 | paired input, R2 repeats one sequence 300× — drives defect 2 |
| `kmer_saturation.fastq` | ~2.5 MB | 8000 | 150 bp random reads → ~1.076M **distinct** 12-mers, saturating the 1M cap — drives defect 3 |
| `phred64.fastq` | ~341 KB | 2000 | quality bytes 66-105 (Phred+64) — drives defect 4 |
| `nruns.fastq` | ~171 KB | 1000 | one 80 bp N-run ×400 + 600 unique reads — drives defect 5 |

**Total fixture size: ~3.2 MB.** Small, synthetic, committed test data — not a
sequencing corpus.

## The test

`bench/tests/pathology_test.sh` builds the `fastcheck` and `fastsim` release
binaries, runs them against the fixtures, and asserts the post-fix behaviour. It
is wired into `scripts/test.sh`, so `bash scripts/test.sh` runs it after the
per-tool cargo suites and folds its result into the grand total. Each defect
prints a PASS/FAIL line naming the measured value.

## Honest caveat — defect 3 is a guard, not a reproduction

The k-mer defect's **40-minute pathology is not reproducible by any small
synthetic FASTQ.** This was verified directly: a faithful stream of 1M distinct
12-mers (2M inserts, heavy count>1 retention so the pre-fix eviction cannot
shrink the map) still finishes in **< 0.2 s** with the pre-fix every-insert
eviction. The 40-minute hang depends on the *real* DRR509062 key distribution
(a large resident count>1 population at the cap), which synthetic random DNA
does not recreate.

So `kmer_saturation.fastq` does what a fixture *can* do: it saturates the 12-mer
space (the necessary condition of the defect) and the test asserts the post-fix
invariant — the scan completes within a generous bound and emits a k-mer
spectrum. It guards against the amortized eviction regressing into a per-insert
scan; it does not, and cannot cheaply, reproduce the full hang. Stated plainly so
no one mistakes a green line for a reproduction.

## Scope

These fixtures assert behaviour at the binary/report level (what the tools emit
for a given input). They complement — do not replace — the per-tool Rust unit
tests, which cover the internal invariants (e.g. the boundary-rule guard itself
is unit-tested in `tools/fastsim/src/artefact.rs`). The corpus's job is the layer
the unit suite missed: the adversarial input.
